# Eval suite

Fresh Claude Code sessions in headless mode doing Automap's jobs along the worked journeys (SPEC §8.7, ADR-0081). Each task runs in a clean repo with only the build toolchain, the `automap` CLI on the PATH and the router skill installed at user scope, given a one-line request and no human input. The runner grades the outcome through `automap verify --json` and writes a machine-readable report: each task's pass, fail or skipped, its duration, and whether the vcpkg binary cache was warm or cold, with the model that answered (ADR-0063).

- `tasks/<id>/task.json`: the request; the starting repo (a directory relative to it, which may be another task's, or none for an empty repo), an overlay copied over it, and any `automap` invocations that bring it to the task's starting point, such as starting the testbed; and what grading requires: the level verification must reach, the library each named slot must hold, libraries the composition must have, and libraries the lock must pin to a private map's variant. The runner commits the starting repo before the session, since the lock pins a private map at a commit.
- Tasks: `testbed-start` (Journey 1's first step, from an empty repo); `testbed-extend` (its extend step: "Add 3D physics." on the started testbed, passing with Jolt in `physics-3d` at probed); `custom-adopt` (Journey 3's adopt step: "Bring this engine under Automap." on Acme's engine, with SDL3, Jolt, an in-house scheduler and renderer and glue of its own, passing probed with the in-house libraries in the composition); `custom-variant` (its patched-library step: the adopted engine, with Acme's private map, and "Use our patched SDL3" with a patch SDL won't take upstream, passing probed with SDL3 pinned to a private variant); and `custom-eject` (its eject step: the adopted, verified engine and a request to leave Automap, passing when the manifest and lock are gone and the repo builds with plain CMake and vcpkg and passes a 120-frame smoke run without the CLI). CI's public-map job checks that `custom-adopt`'s engine adopts to probed with `custom-variant`'s private map, then ejects and builds without Automap.
- The `starter-extend-*` tasks are Journey 2's extend steps (SPEC §2.5), each from the previous step's composition (the runner starts the testbed and extends it through the earlier steps, unverified) and a one-line request for the next library: enkits, mimalloc, spdlog, tracy, glm, flecs, miniaudio, assets (fastgltf and stb-image) and shadercross, each passing probed with the library in its slot. CI's `starter` group builds the starter engine, all thirteen catalog libraries, to probed.
- The report's `measures` are the four v1 measures (SPEC §9.5), each with whether it met its target: `testbed-start`'s time with a warm or cold cache, first-attempt success over the tasks graded, freshness from the map's measures (`go run ./ci/cmd/watch -measure`, which the workflow passes with `-freshness`), and eject.
- The eject measure: after every other task that passes, the runner ejects a copy of the composition the session ended with and builds it the same way; the report's `eject` gives the share of ejected journey compositions that build and pass smoke without Automap (target 100%, ADR-0063).
- `cmd/run`: the runner. `go run ./evals/cmd/run -task testbed-start -automap <cli> -report report.json`. Sessions read the newest published map release, as a developer's do; `-map <dir>` reads a map directory instead.
- `.github/workflows/evals.yml` runs the suite on demand (Actions, "Evals", Run workflow). The Anthropic API key is the repository secret `ANTHROPIC_KEY`, read only by that workflow; a run its spending cap stops is reported as skipped, not failed.
