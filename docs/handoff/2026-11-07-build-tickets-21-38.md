## Things to know

- **GitHub Actions can't open pull requests in this repository** ("GitHub Actions is not permitted to create or approve pull requests"): the curate workflow's last step fails after pushing the branch. The product owner turns it on under the repository's Settings, Actions, General, Workflow permissions; until then, open the pull request by hand from the `curate/<library>-<version>` branch, label it `curation`, and dispatch CI and Verify map on the branch.
- Two curation pull requests both change `map/map.json`'s registry commit; the second to merge conflicts on that line and needs the branch updated (`Publish registry` sets the commit again after the merge anyway).
- vcpkg asks the network where a git registry's reference points on every run unless its lock file (`vcpkg_installed/vcpkg/vcpkg-lock.json`) records it; the CLI writes that file before each vcpkg run (SPEC §5.5).
- A vcpkg tool release's standalone bundle has no ports tree; it reads the curated registry from git at `builtin-baseline`, and its install plan names every port's git tree, which is what `vendor` copies.
- In this session's proxy, GitHub archive downloads return 403 while `git clone` works: vcpkg downloads were seeded by hand with `git archive`, so builds of new public-map libraries run for real only in CI.
- `go test` caches `cmd/automap` results without noticing changes to the CLI it builds: use `-count=1` after changing anything under `internal/`.
- Verify map on a branch (`all=false`, `publish=false`) re-verifies the pieces whose evidence is missing, stale or broken, and prints each failing build's log tail and each uncaught seed's reason: the quickest way to see why a piece is broken.
