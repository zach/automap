- **The loop:** the watcher (`Curate map`, daily) opens one curation session per new upstream release; the session's branch carries the version, its port in the Automap registry when vcpkg lacks it, and the workflow opens the pull request (Actions may open pull requests in this repository since 2026-11-07). CI and Verify map run on the branch; the cooldown gate (`Cooldown gate`, every six hours) merges once the release is seven days old and the evidence green; `Publish registry` republishes the registry from main; `Release map` cuts a release by hand. flecs 4.2.0, tracy 0.15.0, mimalloc 3.6.1 and fastgltf 1.0.1 are upstream without a vcpkg port yet; the watcher brings them back daily.
- **Spending:** curation sessions run automatically, one per new upstream release. Eval runs still need the product owner's approval first.

## Things to know

- Two curation pull requests both change `map/map.json`'s registry commit; the second to merge conflicts on that line and needs the branch updated (`Publish registry` sets the commit again after the merge anyway).
- Every registry commit change makes all evidence stale, since the map is an input to every piece; the next Verify map on main re-verifies everything (about 80 jobs) and commits the fresh evidence. Two runs committing at once rebase with `-X theirs`, the later keeping its own evidence.
- The eval runner gives each task's CLI its own home, so it names its release cache for the CLI (`AUTOMAP_CACHE`); an upgrade task's setup reads the previous release from that cache and the lock records it.
- vcpkg asks the network where a git registry's reference points on every run unless its lock file (`vcpkg_installed/vcpkg/vcpkg-lock.json`) records it; the CLI writes that file before each vcpkg run (SPEC §5.5).
- A vcpkg tool release's standalone bundle has no ports tree; it reads the curated registry from git at `builtin-baseline`, and its install plan names every port's git tree, which is what `vendor` copies.
- In a cloud session's proxy, GitHub archive downloads return 403 while `git clone` works, so builds of public-map libraries run for real only in CI; `gh` GraphQL is blocked, so use `gh api repos/...` (REST) for releases and checks.
- `go test` caches `cmd/automap` results without noticing changes to the CLI it builds: use `-count=1` after changing anything under `internal/`.
- Verify map on a branch (`all=false`, `publish=false`) re-verifies the pieces whose evidence is missing, stale or broken, and prints each failing build's log tail and each uncaught seed's reason: the quickest way to see why a piece is broken.
- GitHub-hosted macOS runners occasionally lose the network to github.com mid-job; a `FETCH_FAILED` there with "Could not connect to server" is the runner, and re-running the failed job clears it.
